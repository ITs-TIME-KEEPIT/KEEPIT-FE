## 사용할 파일

- `src/mocks/demoScenario.ts`: 사용자·옷·신청·거래·단계별 스냅샷 공용 원본.
- `src/mocks/clothItems.ts`: 기존 홈 import 호환용 re-export. 별도 데이터를 복제하지 않음.
- `src/types/clothing.ts`: 홈과 상세가 공유하는 타입.
- `src/components/camera/PhotoCapture.tsx`: 공통 촬영 UI. B 담당이 전달/수령/반납 화면에서 재사용 가능.

현재는 프론트 임시 데이터만 사용하며 API, 서버, 실제 카카오 인증, 업로드, 결제는 연결하지 않습니다. 개발 빌드에서만 시연 로그인을 통과합니다.

## B 담당 사용 예시

```ts
import {
  DEMO_IDS, DEMO_USERS, DEMO_CLOTH_ITEMS,
  DEMO_RENTAL_REQUEST, DEMO_TRADE, DEMO_TRADE_SNAPSHOTS,
} from '../../mocks/demoScenario';

const cloth = DEMO_CLOTH_ITEMS.find(item => item.id === DEMO_IDS.cloth)!;
const request = DEMO_RENTAL_REQUEST;
const owner = DEMO_USERS.owner;
const borrower = DEMO_USERS.borrower;
const stage = DEMO_TRADE_SNAPSHOTS.find(item => item.key === 'accepted')!;
```

신청/거래 화면에서는 `clothId`, `ownerId`, `borrowerId`, `requestId`를 그대로 사용하세요. 이름으로 연결하지 마세요. 같은 옷을 새 ID로 복제하지 마세요.

`DEMO_TRADE_SNAPSHOTS`는 **동일 거래의 시간별 예시**입니다. 전부 한 목록에 넣으면 거래가 중복되므로 필요한 시점 하나만 선택합니다. B 담당 화면의 기존 상태명이 다르면 경계에서 매핑하고 이 파일의 공통 키는 유지합니다. 상태 전환 함수와 두 기기 사이 실시간 동기화는 아직 없습니다. 각 기기가 같은 fixture를 import해도 한 기기의 클릭이 다른 기기에 반영되지는 않습니다.

| key | 보여줄 상태 | 사진 기록 |
| --- | --- | --- |
| requested | 신청 대기 | 등록 |
| accepted | 수락·전달 준비 | 등록 |
| handed-over | 전달 완료·수령 대기 | 등록, 전달 |
| received | 수령 완료·반납 대기 | 등록, 전달, 수령 |
| returned | 반납 완료·등록자 확인 대기 | 등록, 전달, 수령, 반납 |
| completed | 거래 완료 | 4단계 모두 |

현재 A 작업은 로그인·프로필·홈·옷 상세와 공통 촬영 UI입니다. B 담당의 신청/수락/거래 화면과 상태 전환은 추가하지 않았습니다. 상세의 ‘대여 신청’은 B 화면 미구현 안내만 표시합니다.

## 확인이 필요한 부분 / 비워 둔 데이터

- 촬영 정책: Figma는 `1/3·3/3`과 전면·후면·라벨·디테일을 함께 표시하고, 기획에도 3장 촬영/디테일 포함 4장이 함께 기재돼 있습니다. 사용자 요청으로 **필수 장수·다음 버튼 활성 조건·등록 단계 연결은 보류**했습니다. `DEMO_CHECKPOINTS.parts`를 검증 규칙으로 사용하지 마세요.
- 실제 사진 파일이 없으므로 상세는 전면/후면/라벨/디테일 4개의 빈 사진 슬롯을 보여 줍니다. URI를 받은 뒤 `detail.photos[].uri`에 넣고 하자 사진은 `detail.defect.photoUris`에 넣습니다. 카메라 임시 URI는 다른 사람·다른 기기와 공유할 수 없습니다.
- 실측은 문서에 없습니다. 값을 생성하지 않았고 도식에 미입력 치수의 선·라벨은 숨깁니다. 실루엣 원본은 Figma에서 내려받은 SVG입니다. `assets/icons`는 변경하지 않습니다.
- 정가는 fixture에 보존했지만 현재 Figma 옷 상세에는 정가 슬롯이 없습니다. 임의로 UI를 추가하지 않았습니다. 디자이너 확인 위치: **A. 로그인·탐색 → 옷 상세 → 대여 정보 영역**.
- ‘치마’는 현재 디자인의 카테고리에 없어 `category:'하의'`, `sourceCategory:'치마'`로 보존합니다. 새 카테고리 UI는 추가하지 않았습니다.
- 라벤더는 기존 필터 `purple`에, 아이보리는 `white`에 연결하고 원문 색상명은 `colorLabel`에 보존했습니다. `Free`는 기존 타입 `FREE`로 통일했습니다.
- 실측, 계정 전화번호, 가입일, 등록 시각, 조회수, 등록 가능 기간, 택배 거래의 택배비는 미제공입니다. 값이 없으면 `-` 또는 빈 슬롯을 사용합니다. 대여 신청 기간을 옷의 대여 가능 기간으로 바꾸어 쓰지 않았습니다.
- 문서의 11/7 발표 표기와 별개로 대여 일정은 문서의 11/13~11/15를 그대로 보존합니다. 오늘 날짜에 따라 바뀌지 않는 시연 fixture입니다.

## Expo 수동 확인

```powershell
npm install
npm run typecheck
npx expo start
```

기본 `DEMO_LOGIN_MODE='existing'`: 카카오로 시작하기 → 홈 → 라벤더 원피스 → 상세. 실제 카카오 로그인은 호출하지 않습니다.

프로필 흐름: `demoScenario.ts`에서 `DEMO_LOGIN_MODE='new'`로 변경 → 로그인 → 프로필 → 닉네임 시연 중복 확인 → 테스트용 휴대폰 번호 입력 → 시작하기 → 홈. 실사용 번호를 입력할 필요가 없으며 값은 서버로 전송하지 않습니다. 앱을 다시 실행하면 초기화됩니다.

카메라: `DEMO_START_SCREEN='camera'`로 변경하고 Expo에서 앱 재시작 → 실제 기기의 Expo/앱 카메라 권한 허용 → 셔터 → 미리보기 → 재촬영 → 각 부위 선택 → 닫기. 이 화면은 Figma의 ‘전달 직전 상태 사진’ 공통 UI 점검용이며 홈 등록 흐름은 아닙니다. 다음 버튼은 정책 보류로 비활성입니다. 테스트 후 `'login'`으로 되돌리세요. 노트북 카메라 테스트는 진행하지 않았습니다.

카메라 권한 설정은 앱 설정에 포함되어 있습니다. 기존 개발 빌드에 카메라 네이티브 모듈이 없으면 재빌드하거나 같은 SDK를 지원하는 Expo Go에서 확인해야 합니다. 촬영 파일은 캐시 URI로만 보관되며 업로드·갤러리 저장은 하지 않습니다.

## 전달 방법

공용 Git 저장소의 PR로 위 파일들을 함께 전달하는 것이 좋습니다. B 담당은 해당 PR이 반영된 브랜치를 받아 같은 파일을 import하면 됩니다. 코드 블록 복사나 카카오톡으로 데이터만 따로 전달하면 서로 다른 버전이 생기므로, **PR 링크 + 이 문서 경로 + 고정 ID**를 메시지로 공유하세요. 이 작업에서 커밋/push/메시지 전송은 하지 않습니다.

전달 문구 예시:

> 기획자님 중간발표 시나리오 기준 공용 더미 데이터 정리했습니다. `src/mocks/demoScenario.ts`를 함께 사용해 주세요. 수빈/지민, 라벤더 원피스, 11/13~11/15 합정역 직거래 기준이며 사용자·옷·신청·거래 ID를 고정했습니다. `docs/demo-data-handoff.md`에 import 예시와 단계별 스냅샷이 있습니다. 신청/거래 화면도 이 데이터를 연결해 주세요. 사진 원본·실측은 아직 없고 촬영 장수 정책은 확인 전이라 보류했습니다. 두 기기 간 동기화는 아직 없으니 시연할 상태를 맞춰야 합니다.
