# 11/4 등록 프론트 시연

홈 → 옷 올리기 → 카메라 권한 허용 → 전면·후면·라벨 각 1장 → 다음 → 정보 입력 → 거래 가능 지역 선택 → 등록하기 → 완료 → 홈으로 → 새 옷 상세.

전면 1/3, 후면 2/3, 라벨·디테일 3/3. 디테일은 선택입니다. 필수 부위 재촬영 시 다시 촬영하기 전에는 다음이 비활성입니다. 부위 칩을 눌러 촬영 대상을 바꾸고 미리보기를 확인합니다.

개발 모드의 ‘시나리오 정보로 채우기’는 기존 demoScenario.ts의 라벤더 원피스·수빈·마포구·25,000원·하자 설명을 입력 예시로 사용합니다. 실측 118/36/44/35cm, 편도 택배비 3,500원, 대여 불가능 기간 없음은 **프론트 시연용 보완 예시**로 원문 기획 값이 아닙니다. 각 값은 폼에서 수정할 수 있습니다. 기존 시나리오·더미 파일은 수정하지 않습니다. 등록 시 별도의 local-cloth ID로 추가합니다.

백엔드 없이 실제 카메라 촬영·미리보기·재촬영, 필수 입력 검사, 임시저장, 등록 결과의 홈 목록/필터/상세 반영이 작동합니다. 등록 목록·임시저장은 메모리 상태이며 앱을 완전히 재시작하면 초기화됩니다. 사진 URI는 촬영 기기의 캐시 파일입니다. 서버 업로드, 영구 저장, 다른 기기 공유, 실제 알림은 연결하지 않습니다.

## 실제 기기에서 확인

1. VS Code의 KEEPIT-FE에서 `npx expo start`를 실행하고 같은 SDK를 지원하는 Expo Go로 엽니다. 실행 중인 Metro가 있다면 앱을 새로고침합니다.
2. 홈의 ‘옷 올리기’가 준비 중 팝업 대신 촬영 화면을 여는지 확인합니다.
3. 카메라 권한 허용 후 실제 후면 카메라 영상·셔터·미리보기·재촬영을 확인합니다.
4. 전면/후면만 촬영한 상태에서는 다음 비활성, 라벨까지 촬영한 상태에서는 활성인지 확인합니다. 디테일 미촬영이어도 진행합니다.
5. 정보 입력 화면에서 사진 수정 후 입력값이 유지되는지 확인합니다. 임시저장 후 나갔다 다시 진입하는 흐름도 확인합니다.
6. 시나리오 입력 예시를 불러오거나 모든 필수 항목을 직접 입력합니다. 지역 변경, 카테고리별 실측, 컬러 2개 제한, 하자 설명, 택배비 조건을 확인합니다.
7. 등록 완료 → 홈으로 → 목록 최상단의 새 옷 → 상세에서 촬영 사진·입력값·지역·실측을 확인합니다. 기존 더미 항목은 그대로 남아 있어야 합니다.
8. 권한 거절/설정 복귀, 앱 백그라운드 복귀, 카메라 오류 후 재시도를 확인합니다.

실기기 촬영 성공 여부는 자동 검사로 보장하지 않습니다. 타입 검사·Android 번들 생성·순수 로직 검증과 별도로 실제 휴대폰에서 위 순서를 확인해야 합니다.
